# INFERENCE 004 — Zero-Prerequisite Null Condition

**Status:** PROVISIONAL CORE INFERENCE  
**Domain:** Existence / Transition / Persistence  
**Companion consequence:** Null-State Persistence

## Statement

The **Zero-Prerequisite Null Condition** proposes that a null state requires no prior positive structure in order to obtain.

In the limiting case:

```text
nothing requires nothing
```

A positive state, by contrast, requires at least some distinction, event, transition, constraint, or other condition sufficient for something rather than nothing to obtain.

This creates an asymmetry:

```text
something
requires some condition sufficient for positive state

nothing
requires no positive condition
```

The claim is not that a null state must occur in every possible system. Rather, it identifies the null state as the state with the minimal prerequisite burden: no additional positive condition is required merely to remain null.

## Null-State Persistence

If a null state obtains and no transition-producing condition is introduced, the null state persists.

Let `N` denote a null state. Then:

```text
N -> N
```

or, as a fixed-point shorthand:

```text
f(N) = N
```

This is the **Null-State Persistence** consequence.

The relevant intuition is:

> Nothing requires nothing. If nothing changes nothing, nothing remains.

Persistence here does not mean that nullity is metaphysically necessary or that all systems inevitably collapse to nothing. It means that once a null state obtains, continued nullity requires no new positive event.

## Entry-condition distinction

The null state can therefore be treated as a limiting entry condition with zero positive prerequisites.

```text
prerequisite burden(N) = 0
```

Any positive state `S` must satisfy at least one positive condition sufficient to distinguish `S` from `N`.

```text
S != N
therefore
some distinction / transition / condition must obtain
```

This does not by itself prove which positive condition is sufficient, nor whether a given system contains a rule that forces emergence away from nullity.

## Iteration consequence

If the transition rule applied to the null state produces no change, then repeated application preserves the null state:

```text
N_0 = N
N_1 = f(N_0) = N
N_2 = f(N_1) = N
...
N_t = N
```

Informally:

> If nothing happens, nothing happens again.

This is not circular explanation so much as a statement of the absence of a state-changing condition.

## Asymmetry with existence

The inference therefore shifts explanatory burden toward positive existence:

```text
null persistence
needs no positive transition

positive existence
requires explanation of the distinction or transition by which it obtains
```

The framework should therefore avoid treating existence and non-existence as structurally symmetric starting points.

## Relation to trajectory

A trajectory requires state differentiation across time or at minimum a positively instantiated state capable of being carried forward.

Where no distinction, state, or transition obtains, there is no positive trajectory to preserve.

Accordingly:

```text
trajectory
requires something to be carried

null state
requires nothing to be carried
```

This connects the null-state inference to continuity work without collapsing the two: continuity concerns how an instantiated trajectory persists through change; null-state persistence concerns the limiting case in which no positive transition occurs.

## Research boundary

This inference does **not** establish:

- that absolute metaphysical nothingness is physically realizable;
- that the universe began from nothing;
- that nothingness is inevitable;
- that quantum vacuum states are equivalent to philosophical nothingness;
- that every formal system contains a null state;
- or that no spontaneous transition from a null state is possible under a specified rule set.

Those questions require additional definitions and evidence.

The present inference is narrower:

> A null state has zero positive prerequisites for remaining null. Once nullity obtains, persistence of nullity requires no new positive event unless the system contains a rule that forces transition away from it.

## Locked short form

> **Zero-Prerequisite Null Condition:** Nothing requires nothing.  
> **Null-State Persistence:** If nothing changes nothing, nothing remains.
